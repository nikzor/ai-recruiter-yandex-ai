# Flutter Interview Lab

Приложение для тренировочного интервью по Flutter и демонстрации возможностей Yandex AI Studio. YandexGPT задаёт вопросы и готовит итоговый разбор, SpeechKit озвучивает вопросы и расшифровывает голосовые ответы; отдельный режим Realtime передаёт речь в обе стороны по WebSocket. Интерфейс и интервью — на русском языке.

Это учебный проект: оценка помогает подготовиться к собеседованию и не является решением о найме.

## Основной функционал

- **Четыре уровня сложности:** Intern, Junior, Middle и Senior.
- **До пяти основных вопросов за интервью:** по одному вопросу на темы Dart, виджетов, состояния, данных и качества кода. В облачном режиме модель учитывает предыдущие ответы.
- **Голосовой режим по умолчанию:** автоматическое озвучивание вопроса, запись по нажатию, расшифровка во время речи, завершение записи пользователем.
- **Непрерывный диалог Realtime:** микрофон включается при старте интервью. После ответа и паузы ассистент сам задаёт уточнение или следующий вопрос. Можно перебить озвучивание; единственное действие в разговоре — «Завершить интервью». После пяти вопросов отчёт создаётся автоматически.
- **Текстовый режим:** отдельный сценарий с ручной отправкой ответов; обычный голосовой режим также сохраняется. Во время Realtime режим общения не меняется.
- **Расшифровка:** в Realtime отображается ход речи, ответы принимаются автоматически после паузы. В обычном голосовом режиме расшифровку можно исправить и отправить вручную.
- **История:** предыдущие вопросы и ответы доступны в свёрнутом блоке.
- **Итоговый отчёт:** балл из 100, сильные стороны, пробелы, рекомендации и разбор каждого обсуждённого вопроса с оценкой 0–4. Досрочное завершение Realtime даёт отчёт по пройденной части; без ответов оценки нет.
- **Экспорт:** кнопка «Скачать отчёт» сохраняет сессию с результатами в JSON.
- **Восстановление:** сохранённая на сервере сессия восстанавливается после обновления той же вкладки. Обычный неотправленный черновик не восстанавливается; в Realtime сервер сохраняет полученную расшифровку для восстановления.
- **Демонстрационный режим:** полный текстовый сценарий без облачных ключей и запросов.

## Быстрый запуск

Требуются Node.js **22.12+** и npm. Команды выполняются из корня проекта:

```sh
npm ci
npm run dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). Команда запускает Vite и Node.js-сервер; Ctrl+C останавливает оба процесса.

Если `.env` отсутствует, используется `AI_MODE=mock`. Если файл уже существует, режим определяется им. В mock выберите **«Текстом»**: распознавание и озвучивание выключены. Вопросы берутся из готового банка, за каждый ответ выставляется 2/4, итог — 50/100 независимо от содержания. Это демонстрация сценария, а не проверка знаний. Интернет нужен для установки зависимостей; после установки mock работает локально.

## Подключение Yandex AI Studio

Подготовьте каталог Yandex Cloud с оплатой и сервисный аккаунт с доступом к генерации текста, синтезу и распознаванию речи. Роли и области действия ключа описаны в [документации интеграции](docs/YANDEX-AI-STUDIO.md#доступ-и-конфигурация).

Скопируйте `.env.example` в `.env`, если файла ещё нет. Существующий файл с ключом перезаписывать не нужно. Пример настроек:

```dotenv
AI_MODE=yandex
API_KEY=ваш_ключ
YANDEX_FOLDER_ID=идентификатор_каталога
YANDEX_MODEL=yandexgpt-5.1
PORT=3001
TTS_ENABLED=true
TTS_VOICE=filipp
STT_ENABLED=true
REALTIME_ENABLED=true
REALTIME_MODEL=speech-realtime-deepseek-v4-flash
REALTIME_VOICE=filipp
REALTIME_TTS=speechkit
```

Перезапустите приложение. Надпись «Yandex AI Studio» обозначает выбранный режим; доступ к облачным API проверяется при выполнении запросов. `YANDEX_API_KEY` поддерживается как запасное имя переменной; при наличии обоих ключей адаптеры используют непустой `API_KEY`.

Ключ читает только сервер. `.env` исключён из Git; секреты нельзя помещать в переменные `VITE_*`. В облако передаются история интервью, текст для озвучивания и аудио во время записи. Облачные вызовы оплачиваются по потреблению. Без повторов текстовое интервью требует шесть запросов к YandexGPT; голосовой режим дополнительно использует TTS и STT.

В обычном голосовом режиме текущее озвучивание: **SpeechKit REST API v1, голос `filipp`, скорость `1.0`**, исходный текст без словаря произношения. LiveTTS, замедление и фонетические замены из экспериментов сейчас не используются. «Диалог Realtime» использует Realtime для распознавания и определения пауз, а готовые вопросы по умолчанию озвучивает быстрым SpeechKit MP3. Настройка `REALTIME_TTS=native` возвращает нативное озвучивание Realtime. Режим использует отдельную речевую модель и требует роли `ai.models.user` и scope ключа `yc.ai.foundationModels.execute`; [настройка и протокол](docs/REALTIME.md).

## Как пройти интервью

Для Realtime выберите «Диалог Realtime», уровень и нажмите «Начать интервью». Разрешите микрофон: ассистент озвучит вопрос и будет слушать ответ. Пауза завершает реплику и запускает уточнение либо следующий вопрос. Не требуется отправлять текст или перезапускать запись между вопросами. На один основной вопрос возможно одно уточнение.

Кнопка «Завершить интервью» заканчивает весь разговор и готовит отчёт по полученным ответам. После пятого вопроса это происходит автоматически. При сбое можно продолжить разговор или завершить его по сохранённой части; если подготовка отчёта не удалась, её можно повторить. После перезагрузки вкладки для возврата к микрофону требуется «Продолжить разговор».

В обычном голосовом режиме нажмите «Ответить голосом», затем «Закончить ответ», проверьте текст и нажмите «Отправить ответ». Текстовый режим использует тот же ручной сценарий. После пяти ответов в этих режимах нажмите «Получить отчёт».

Длина ответа — до 4000 символов. Для микрофона нужен поддерживающий Web Audio браузер и безопасный контекст: HTTPS или локальный `127.0.0.1`. Микрофон закрывается при завершении или сбое; неотправленное аудио после перезагрузки не восстанавливается.

## Проверка

```sh
npm run check
```

Команда запускает автотесты и production-сборку. Платные API не вызываются.

Для проверки настоящего облака предусмотрены отдельные команды:

| Команда | Проверка | Платные обращения без повторов |
| --- | --- | --- |
| `npm run smoke:yandex` | Пять вопросов, отчёт, восстановление и удаление сессии | 6 запросов YandexGPT |
| `npm run smoke:tts` | Синтез учебного вопроса в MP3; путь к файлу выводится в консоль | 1 запрос TTS |
| `npm run smoke:realtime` | Два автоматических раунда через локальный мост, облачный звук и VAD, досрочное завершение; вопросы/отчёт подменены | 1 Realtime-сессия и 3 синтеза SpeechKit в быстром режиме |
| `npm run smoke:stt` | Синтез учебной фразы в PCM и её потоковое распознавание через сервер | 1 запрос TTS и 1 поток STT |

Эти команды требуют заполненного `.env`. Синтетическое аудио не заменяет ручную проверку физического микрофона и качества произношения.

## Запуск собранного приложения

```sh
npm run build
npm start
```

По умолчанию приложение доступно на [http://127.0.0.1:3001](http://127.0.0.1:3001). Node.js раздаёт `dist/`, HTTP API и WebSocket. `vite preview` не заменяет сервер приложения.

Если порт занят, для собранного приложения можно выбрать другой:

```sh
PORT=3002 npm start
```

В режиме разработки backend должен соответствовать адресу proxy в `vite.config.js`; по умолчанию это порт 3001.

## Ограничения

Сессии хранятся только в памяти сервера: до 100 сессий, срок — 2 часа с последнего успешного изменения интервью. Перезапуск сервера удаляет их. Просмотр сессии и обычные TTS/STT-операции не продлевают этот срок; сохранение ответов в Realtime обновляет сессию.

Проект предназначен для локальной демонстрации: нет аккаунтов, базы данных и защиты облачного бюджета для публичного сервиса. Не реализованы загрузка резюме и потоковая генерация текста вопросов. Realtime принимает ответы после паузы: случайная остановка речи может быть воспринята как конец реплики. Проверка качества распознавания и акустического эха на реальных устройствах остаётся отдельным этапом.
